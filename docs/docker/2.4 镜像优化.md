# 镜像优化

## 镜像大小的重要性

镜像大小直接影响：
1. 拉取和推送镜像的速度
2. 存储成本
3. 部署速度
4. 安全性（镜像越小，攻击面越小）

## 优化策略

### 1. 选择合适的基础镜像

#### 使用 Alpine 镜像

```dockerfile
# 推荐：使用 Alpine
FROM node:18-alpine
FROM python:3.11-slim
FROM nginx:alpine

# 不推荐：使用完整版本
FROM node:18
FROM python:3.11
FROM nginx
```

#### 使用 Distroless 镜像

```dockerfile
# 推荐：使用 Distroless（Google 提供的极简镜像）
FROM gcr.io/distroless/nodejs18
FROM gcr.io/distroless/python3

# 优点：只包含应用运行时，没有包管理器、shell 等
# 缺点：调试困难，不能进入容器
```

#### 使用 Scratch 镜像

```dockerfile
# 推荐：对于静态编译的语言，使用 scratch
FROM scratch
COPY --from=builder /app/app .
CMD ["./app"]

# 注意：scratch 是空镜像，没有任何文件系统
```

### 2. 多阶段构建

```dockerfile
# 推荐：使用多阶段构建
FROM golang:1.21 AS builder
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o app

FROM alpine:latest
RUN apk --no-cache add ca-certificates
WORKDIR /app
COPY --from=builder /app/app .
CMD ["./app"]

# 不推荐：单阶段构建
FROM golang:1.21
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o app
CMD ["./app"]
```

### 3. 合并 RUN 指令

```dockerfile
# 推荐：合并 RUN 指令
RUN apt-get update && \
    apt-get install -y \
        curl \
        vim \
        git \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*

# 不推荐：多个 RUN 指令
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y vim
RUN apt-get install -y git
```

### 4. 清理不必要的文件

```dockerfile
# 推荐：清理缓存和临时文件
RUN apt-get update && \
    apt-get install -y python3-pip && \
    pip3 install --no-cache-dir -r requirements.txt && \
    apt-get remove -y python3-pip && \
    apt-get autoremove -y && \
    apt-get clean && \
    rm -rf /var/lib/apt/lists/*

# 不推荐：不清理缓存
RUN apt-get update
RUN apt-get install -y python3-pip
RUN pip3 install -r requirements.txt
```

### 6. 优化依赖安装

```dockerfile
# 推荐：只安装生产依赖
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
CMD ["node", "index.js"]

# 不推荐：安装所有依赖
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
CMD ["node", "index.js"]
```

### 7. 使用构建参数

```dockerfile
# 推荐：使用构建参数控制环境
ARG ENV=production
FROM node:18-alpine AS base
WORKDIR /app

FROM base AS deps
COPY package*.json ./
RUN npm ci

FROM base AS build
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build

FROM node:18-alpine AS runtime
WORKDIR /app
COPY --from=build /app/dist ./dist
COPY package.json ./
ENV NODE_ENV=${ENV}
CMD ["node", "dist/index.js"]

# 构建
# docker build --build-arg ENV=production -t myapp:prod .
```

### 8. 压缩二进制文件

```dockerfile
# Go 应用：使用编译选项减小体积
FROM golang:1.21 AS builder
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags="-w -s" \
    -trimpath \
    -o app

# Rust 应用：使用 release 模式
FROM rust:1.75 AS builder
WORKDIR /app
COPY . .
RUN cargo build --release
```

### 9. 使用 UPX 压缩

```dockerfile
FROM alpine:latest AS compressor
RUN apk --no-cache add upx
COPY --from=builder /app/app .
RUN upx --best --lzma app

FROM alpine:latest
COPY --from=compressor /app/app .
CMD ["./app"]
```

### 10. 利用层缓存

```dockerfile
# 推荐：将不常变化的指令放在前面
FROM python:3.11-slim
WORKDIR /app

# 这一步会被缓存（如果 requirements.txt 没有变化）
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 这一步不会被缓存（如果源代码有变化）
COPY . .

# 不推荐：将常变化的指令放在前面
FROM python:3.11-slim
WORKDIR /app
COPY . .
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
```

## 实际优化示例

### Python 应用优化

```dockerfile
# 优化前
FROM python:3.11
WORKDIR /app
COPY . .
RUN pip install -r requirements.txt
CMD ["python", "app.py"]
# 镜像大小：约 900MB

# 优化后
FROM python:3.11-slim

WORKDIR /app

# 复制依赖文件
COPY requirements.txt .

# 安装依赖
RUN pip install --no-cache-dir -r requirements.txt

# 复制应用代码
COPY . .

# 创建非 root 用户
RUN useradd -m -u 1000 appuser && \
    chown -R appuser:appuser /app

USER appuser

EXPOSE 8000

CMD ["python", "app.py"]
# 镜像大小：约 150MB
```

### Node.js 应用优化

```dockerfile
# 优化前
FROM node:18
WORKDIR /app
COPY . .
RUN npm install
RUN npm run build
CMD ["node", "dist/index.js"]
# 镜像大小：约 1.2GB

# 优化后
FROM node:18-alpine AS builder

WORKDIR /app

# 复制 package 文件
COPY package*.json ./

# 安装依赖
RUN npm ci

# 复制源代码
COPY . .

# 构建应用
RUN npm run build

FROM node:18-alpine

WORKDIR /app

# 复制构建产物
COPY --from=builder /app/dist ./dist
COPY package.json ./

# 创建非 root 用户
RUN addgroup -g 1000 appuser && \
    adduser -D -u 1000 -G appuser appuser && \
    chown -R appuser:appuser /app

USER appuser

EXPOSE 3000

CMD ["node", "dist/index.js"]
# 镜像大小：约 180MB
```

### Go 应用优化

```dockerfile
# 优化前
FROM golang:1.21
WORKDIR /app
COPY . .
RUN go build -o app
CMD ["./app"]
# 镜像大小：约 850MB

# 优化后
FROM golang:1.21 AS builder

WORKDIR /app

# 复制 go mod 文件
COPY go.* ./

# 下载依赖
RUN go mod download

# 复制源代码
COPY . .

# 构建应用
RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags="-w -s" \
    -trimpath \
    -o app

FROM alpine:latest

# 安装 CA 证书
RUN apk --no-cache add ca-certificates

WORKDIR /app

# 复制二进制文件
COPY --from=builder /app/app .

# 创建非 root 用户
RUN addgroup -g 1000 appuser && \
    adduser -D -u 1000 -G appuser appuser && \
    chown -R appuser:appuser /app

USER appuser

EXPOSE 8080

CMD ["./app"]
# 镜像大小：约 15MB
```

## 镜像分析工具

### 1. docker history

```bash
# 查看镜像历史
docker history <镜像名>

# 查看镜像历史（不显示截断）
docker history --no-trunc <镜像名>

# 查看镜像历史（显示人类可读的大小）
docker history --human <镜像名>
```

### 2. docker diff

```bash
# 查看容器的文件系统变化
docker diff <容器ID或名称>
```

### 3. dive

```bash
# 安装 dive
# macOS
brew install dive

# Linux
wget https://github.com/wagoodman/dive/releases/download/v0.10.0/dive_0.10.0_linux_amd64.deb
sudo apt install ./dive_0.10.0_linux_amd64.deb

# 分析镜像
dive <镜像名>
```

### 4. docker-slim

```bash
# 安装 docker-slim
# macOS
brew install docker-slim

# Linux
curl -sSL https://raw.githubusercontent.com/docker-slim/docker-slim/master/scripts/install-dockerslim.sh | bash

# 优化镜像
docker-slim build <镜像名>
```

## 总结

镜像优化是 Docker 使用中的重要环节，通过合理的优化策略，可以：
1. 显著减小镜像大小
2. 提高拉取和推送速度
3. 降低存储成本
4. 提高安全性
5. 加快部署速度

建议在构建镜像时，始终考虑优化策略，并使用镜像分析工具来评估优化效果。
