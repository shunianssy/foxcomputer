# 日志管理

## 日志管理简介

Docker 提供了强大的日志管理功能，可以收集、存储和查看容器的日志。合理管理日志对于应用的监控、调试和维护至关重要。

## Docker 日志驱动

### 1. json-file 驱动（默认）

json-file 是 Docker 的默认日志驱动，将日志以 JSON 格式存储在文件中。

```bash
# 使用默认日志驱动
docker run -d --name my-app myapp:latest

# 查看日志
docker logs my-app
```

### 2. syslog 驱动

将日志发送到 syslog 服务器。

```bash
# 使用 syslog 驱动
docker run -d \
  --name my-app \
  --log-driver syslog \
  --log-opt syslog-address=tcp://192.168.1.100:514 \
  myapp:latest
```

### 3. journald 驱动

将日志发送到 systemd journal。

```bash
# 使用 journald 驱动
docker run -d \
  --name my-app \
  --log-driver journald \
  myapp:latest

# 查看日志
journalctl CONTAINER_NAME=my-app
```

### 4. fluentd 驱动

将日志发送到 Fluentd。

```bash
# 使用 fluentd 驱动
docker run -d \
  --name my-app \
  --log-driver fluentd \
  --log-opt fluentd-address=localhost:24224 \
  --log-opt tag=docker.myapp \
  myapp:latest
```

### 5. awslogs 驱动

将日志发送到 AWS CloudWatch Logs。

```bash
# 使用 awslogs 驱动
docker run -d \
  --name my-app \
  --log-driver awslogs \
  --log-opt awslogs-region=us-west-2 \
  --log-opt awslogs-group=my-log-group \
  --log-opt awslogs-stream=my-log-stream \
  myapp:latest
```

## 查看日志

### 基本日志查看

```bash
# 查看容器日志
docker logs <容器ID或名称>

# 查看最后 N 行日志
docker logs --tail 100 <容器ID或名称>

# 实时查看日志
docker logs -f <容器ID或名称>

# 查看最近时间的日志
docker logs --since 10m <容器ID或名称>
docker logs --since 1h <容器ID或名称>
docker logs --since 2024-01-01T00:00:00 <容器ID或名称>

# 查看特定时间段的日志
docker logs --since 10m --until 5m <容器ID或名称>
```

### 格式化日志输出

```bash
# 显示时间戳
docker logs -t <容器ID或名称>

# 显示完整日志（不截断）
docker logs --tail 0 -f <容器ID或名称>

# 组合使用
docker logs -f --tail 100 -t <容器ID或名称>
```

### 过滤日志

```bash
# 使用 grep 过滤日志
docker logs my-app | grep ERROR
docker logs my-app | grep "2024-01-01"

# 使用多个 grep 条件
docker logs my-app | grep ERROR | grep "database"

# 排除特定内容
docker logs my-app | grep -v DEBUG
```

## 日志配置

### 配置日志大小限制

```bash
# 运行容器时配置日志
docker run -d \
  --name my-app \
  --log-opt max-size=10m \
  --log-opt max-file=3 \
  myapp:latest

# 在 daemon.json 中全局配置
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

### 配置日志轮转

```bash
# 配置日志轮转
docker run -d \
  --name my-app \
  --log-opt max-size=10m \
  --log-opt max-file=5 \
  --log-opt compress=true \
  myapp:latest
```

### 配置日志标签

```bash
# 添加日志标签
docker run -d \
  --name my-app \
  --log-opt labels=app,env \
  --label app=myapp \
  --label env=production \
  myapp:latest
```

## 应用日志最佳实践

### 1. 输出到标准输出和标准错误

```python
# 推荐：输出到标准输出
import logging
import sys

logging.basicConfig(
    stream=sys.stdout,
    level=logging.INFO,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s'
)

logger = logging.getLogger(__name__)

logger.info('Application started')
logger.error('An error occurred')
```

```javascript
// 推荐：输出到标准输出
const winston = require('winston');

const logger = winston.createLogger({
  transports: [
    new winston.transports.Console({
      format: winston.format.combine(
        winston.format.timestamp(),
        winston.format.json()
      )
    })
  ]
});

logger.info('Application started');
logger.error('An error occurred');
```

### 2. 使用结构化日志

```python
# 推荐：使用结构化日志
import logging
import json

class StructuredLogger:
    def __init__(self, name):
        self.logger = logging.getLogger(name)
        self.logger.setLevel(logging.INFO)
        handler = logging.StreamHandler()
        handler.setFormatter(logging.Formatter('%(message)s'))
        self.logger.addHandler(handler)
    
    def log(self, level, message, **kwargs):
        log_entry = {
            'level': level,
            'message': message,
            **kwargs
        }
        self.logger.info(json.dumps(log_entry))

logger = StructuredLogger('app')
logger.log('INFO', 'User logged in', user_id=123, ip='192.168.1.1')
```

### 3. 日志级别

```python
# 推荐：使用适当的日志级别
import logging

logger = logging.getLogger(__name__)

# DEBUG: 详细的调试信息
logger.debug('Variable value: %s', variable)

# INFO: 一般信息
logger.info('Application started')

# WARNING: 警告信息
logger.warning('Cache miss for key: %s', key)

# ERROR: 错误信息
logger.error('Failed to connect to database: %s', error)

# CRITICAL: 严重错误
logger.critical('Application cannot continue')
```

## 日志分析

### 1. 使用日志分析工具

```bash
# 使用 GoAccess 分析访问日志
docker logs my-app | goaccess -

# 使用 awk 分析日志
docker logs my-app | awk '{print $1}' | sort | uniq -c | sort -nr

# 使用 sed 提取特定信息
docker logs my-app | sed -n '/ERROR/p'
```

### 2. 日志统计

```bash
# 统计错误数量
docker logs my-app | grep -c ERROR

# 统计每个日志级别的数量
docker logs my-app | grep -oP 'level":"\K\w+' | sort | uniq -c

# 统计最频繁的错误
docker logs my-app | grep ERROR | sort | uniq -c | sort -nr | head -10
```

## 日志备份

### 1. 备份日志文件

```bash
# 备份容器日志
docker cp <容器ID或名称>:/var/lib/docker/containers/<容器ID>/<容器ID>-json.log ./backup/

# 压缩日志备份
tar czf logs-backup-$(date +%Y%m%d).tar.gz ./backup/
```

### 2. 自动备份脚本

```bash
#!/bin/bash
# backup-logs.sh

BACKUP_DIR="/backup/logs"
DATE=$(date +%Y%m%d_%H%M%S)

# 创建备份目录
mkdir -p ${BACKUP_DIR}

# 备份所有容器日志
for container in $(docker ps -q); do
    container_name=$(docker inspect --format='{{.Name}}' $container | sed 's/\///')
    docker cp $container:/var/lib/docker/containers/$container/$container-json.log \
        ${BACKUP_DIR}/${container_name}_${DATE}.log
done

# 压缩备份
tar czf ${BACKUP_DIR}/logs-backup-${DATE}.tar.gz ${BACKUP_DIR}/*.log

# 删除未压缩的日志文件
rm ${BACKUP_DIR}/*.log
```

## 日志清理

### 1. 清理旧日志

```bash
# 清理 7 天前的日志
find /var/lib/docker/containers/ -name "*.log" -mtime +7 -delete

# 清理超过 100MB 的日志文件
find /var/lib/docker/containers/ -name "*.log" -size +100M -delete
```

### 2. 自动清理脚本

```bash
#!/bin/bash
# clean-logs.sh

# 清理 7 天前的日志
find /var/lib/docker/containers/ -name "*.log" -mtime +7 -delete

# 清理超过 100MB 的日志文件
find /var/lib/docker/containers/ -name "*.log" -size +100M -delete

echo "Log cleanup completed at $(date)"
```

```bash

# 发送错误告警
docker logs -f my-app | grep --line-buffered ERROR | while read line; do
    echo "$line" | mail -s "Error in my-app" admin@example.com
done
```
