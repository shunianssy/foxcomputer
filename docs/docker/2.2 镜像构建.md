# 镜像构建

## 构建镜像

### 基本构建命令

```bash
# 基本构建
docker build -t <镜像名>:<标签> <路径>

# 使用当前目录的 Dockerfile
docker build -t myapp:1.0 .

# 使用指定的 Dockerfile
docker build -t myapp:1.0 -f Dockerfile.prod .

# 指定构建上下文
docker build -t myapp:1.0 /path/to/context
```

### 构建选项

```bash
# 不使用缓存
docker build --no-cache -t myapp:1.0 .

# 拉取最新的基础镜像
docker build --pull -t myapp:1.0 .

# 显示构建过程
docker build --progress=plain -t myapp:1.0 .

# 限制构建并行度
docker build --build-arg BUILDKIT_INLINE_CACHE=1 -t myapp:1.0 .

# 设置构建参数
docker build --build-arg VERSION=2.0 -t myapp:1.0 .

# 指定平台
docker build --platform linux/amd64 -t myapp:1.0 .
```

## 构建参数

### ARG 指令

在 Dockerfile 中定义构建参数：

```dockerfile
# 定义构建参数
ARG VERSION=1.0
ARG BUILD_DATE

# 使用构建参数
LABEL version=${VERSION}
LABEL build-date=${BUILD_DATE}

# 在构建时传递
# docker build --build-arg VERSION=2.0 --build-arg BUILD_DATE=$(date +%Y-%m-%d) .
```

### 常用构建参数

```bash
# 传递版本号
docker build --build-arg VERSION=2.0 -t myapp:2.0 .

# 传递环境
docker build --build-arg ENV=production -t myapp:prod .

# 传递构建时间
docker build --build-arg BUILD_DATE=$(date +%Y-%m-%d) -t myapp:1.0 .

# 传递多个参数
docker build \
  --build-arg VERSION=2.0 \
  --build-arg ENV=production \
  --build-arg BUILD_DATE=$(date +%Y-%m-%d) \
  -t myapp:2.0 .
```

## 构建缓存

### 利用缓存

Docker 会缓存每一步的构建结果，如果指令和文件没有变化，就会使用缓存：

```dockerfile
# 这一步会被缓存
FROM python:3.11-slim

# 这一步会被缓存
WORKDIR /app

# 这一步会被缓存（如果 requirements.txt 没有变化）
COPY requirements.txt .
RUN pip install -r requirements.txt

# 这一步不会被缓存（如果源代码有变化）
COPY . .
```

### 强制不使用缓存

```bash
# 完全不使用缓存
docker build --no-cache -t myapp:1.0 .

# 从特定指令开始不使用缓存
docker build --no-cache --target=builder -t myapp:1.0 .
```

### 缓存失效

以下情况会导致缓存失效：
1. Dockerfile 中的指令发生变化
2. 复制的文件内容发生变化
3. 挂载的目录内容发生变化

## 多阶段构建

### 基本概念

多阶段构建允许在一个 Dockerfile 中使用多个 FROM 指令，每个 FROM 指令开始一个新的构建阶段。

### Node.js 应用示例

```dockerfile
# 构建阶段
FROM node:18 AS builder

WORKDIR /app

# 复制 package 文件
COPY package*.json ./

# 安装依赖
RUN npm ci

# 复制源代码
COPY . .

# 构建应用
RUN npm run build

# 运行阶段
FROM node:18-alpine AS runtime

WORKDIR /app

# 从构建阶段复制构建产物
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./

# 暴露端口
EXPOSE 3000

# 启动应用
CMD ["node", "dist/index.js"]
```

### Python 应用示例

```dockerfile
# 构建阶段
FROM python:3.11 AS builder

WORKDIR /app

# 复制依赖文件
COPY requirements.txt .

# 安装依赖
RUN pip install --user -r requirements.txt

# 运行阶段
FROM python:3.11-slim AS runtime

WORKDIR /app

# 从构建阶段复制依赖
COPY --from=builder /root/.local /root/.local

# 复制应用代码
COPY . .

# 设置环境变量
ENV PATH=/root/.local/bin:$PATH

# 暴露端口
EXPOSE 8000

# 启动应用
CMD ["python", "app.py"]
```

### Go 应用示例

```dockerfile
# 构建阶段
FROM golang:1.21 AS builder

WORKDIR /app

# 复制 go mod 文件
COPY go.* ./

# 下载依赖
RUN go mod download

# 复制源代码
COPY . .

# 构建应用
RUN CGO_ENABLED=0 GOOS=linux go build -o app

# 运行阶段
FROM alpine:latest AS runtime

# 安装 CA 证书
RUN apk --no-cache add ca-certificates

WORKDIR /app

# 从构建阶段复制二进制文件
COPY --from=builder /app/app .

# 暴露端口
EXPOSE 8080

# 启动应用
CMD ["./app"]
```

## 构建上下文

### 理解构建上下文

构建上下文是指在构建时传递给 Docker 守护进程的文件和目录。

```bash
# 当前目录作为构建上下文
docker build -t myapp:1.0 .

# 指定目录作为构建上下文
docker build -t myapp:1.0 /path/to/app

# 使用远程仓库
docker build -t myapp:1.0 https://github.com/user/repo.git
```

## 构建最佳实践

### 1. 选择合适的基础镜像

```dockerfile
# 推荐：使用官方镜像
FROM python:3.11-slim
FROM node:18-alpine

# 不推荐：从零开始
FROM scratch
# 然后手动安装所有依赖
```

### 2. 最小化镜像层数

```dockerfile
# 推荐：合并 RUN 指令
RUN apt-get update && \
    apt-get install -y curl vim git && \
    apt-get clean && \
    rm -rf /var/lib/apt/lists/*

# 不推荐：多个 RUN 指令
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y vim
```

### 3. 合理利用缓存

```dockerfile
# 推荐：将不常变化的指令放在前面
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .

# 不推荐：将常变化的指令放在前面
COPY . .
RUN pip install -r requirements.txt
```

### 4. 使用多阶段构建

```dockerfile
# 推荐：多阶段构建
FROM node:18 AS builder
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html

# 不推荐：单阶段构建
FROM node:18
RUN npm install && npm run build
CMD ["node", "dist/index.js"]
```

### 5. 清理不必要的文件

```dockerfile
# 推荐：清理缓存和临时文件
RUN apt-get update && \
    apt-get install -y curl && \
    apt-get clean && \
    rm -rf /var/lib/apt/lists/*

# 不推荐：不清理缓存
RUN apt-get update
RUN apt-get install -y curl
```

## 构建优化技巧

### 1. 使用 BuildKit

BuildKit 是 Docker 的下一代构建工具，提供了更好的性能和功能：

```bash
# 启用 BuildKit
export DOCKER_BUILDKIT=1

# 使用 BuildKit 构建
docker build -t myapp:1.0 .

# 在 Dockerfile 中使用
# syntax=docker/dockerfile:1.4
FROM python:3.11-slim
```

### 2. 并行构建

BuildKit 支持并行构建，可以显著提高构建速度：

```dockerfile
# 并行安装依赖
COPY requirements.txt requirements-dev.txt ./
RUN pip install -r requirements.txt && \
    pip install -r requirements-dev.txt
```

### 3. 使用缓存挂载

BuildKit 支持缓存挂载，可以缓存包管理器的下载：

```dockerfile
# 缓存 pip 下载
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install -r requirements.txt

# 缓存 npm 下载
RUN --mount=type=cache,target=/root/.npm \
    npm ci
```

### 4. 使用 SSH 密钥

BuildKit 支持在构建时使用 SSH 密钥：

```bash
# 使用 SSH 密钥构建
docker build --ssh default -t myapp:1.0 .
```

```dockerfile
# 在 Dockerfile 中使用 SSH
RUN --mount=type=ssh \
    git clone git@github.com:user/repo.git
```

## 构建调试

### 查看构建日志

```bash
# 显示详细构建日志
docker build --progress=plain -t myapp:1.0 .

# 只显示错误
docker build --progress=plain 2>&1 | grep -i error
```

### 检查中间镜像

```bash
# 查看构建过程中的中间镜像
docker build --progress=plain -t myapp:1.0 . 2>&1 | grep -i "step"

# 查看特定步骤的中间镜像
docker images | grep <image_id>
```

### 进入构建容器

```bash
# 使用 --target 选项构建特定阶段
docker build --target builder -t myapp:builder .

# 进入构建容器
docker run -it myapp:builder bash
```
