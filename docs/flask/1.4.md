# 1.4 运行与调试

虽然你可以直接运行 `python app.py`，但更推荐使用 Flask 自带的命令行工具。

## 1. 启动服务

在终端输入：

```bash
flask run
```

你会看到一行提示：`Running on http://127.0.0.1:5000`。打开浏览器访问它，你就能看到你的页面了！

### 常用启动参数

```bash
# 指定端口
flask run --port 8080

# 允许外部访问
flask run --host 0.0.0.0

# 同时指定
flask run --host 0.0.0.0 --port 8080
```

## 2. 开启调试模式（强烈建议）

在开发阶段，如果你改了代码，肯定不想每次都手动重启服务器。开启调试模式（Debug Mode）后，代码一存盘，服务器会自动重启。

### 方式一：环境变量

**Windows (CMD):**
```bash
set FLASK_DEBUG=1
flask run
```

**Windows (PowerShell):**
```powershell
$env:FLASK_DEBUG = "1"
flask run
```

**macOS / Linux:**
```bash
export FLASK_DEBUG=1
flask run
```

### 方式二：使用 .env 文件

创建 `.env` 文件：

```env
FLASK_APP=app.py
FLASK_DEBUG=1
```

然后直接运行：

```bash
flask run
```

### 方式三：在代码中设置（不推荐）

```python
if __name__ == '__main__':
    app.run(debug=True)
```

### 方式四：Flask 2.3+ 新语法

```bash
flask run --debug
```

## 3. 调试模式的强大功能

### 自动重载（Auto-reload）

修改代码后，服务器自动重启，无需手动操作。

### 交互式调试器（Interactive Debugger）

当程序出错时，浏览器会显示一个交互式调试页面：

- 查看完整的错误堆栈
- 在浏览器中执行 Python 代码
- 检查变量值

### 错误信息展示

详细的错误信息帮助你快速定位问题。

## 4. 使用 Python 调试器

### 方式一：在代码中设置断点

```python
@app.route('/')
def index():
    import pdb; pdb.set_trace()  # 程序会在这里暂停
    return 'Hello'
```

### 方式二：使用 breakpoint()（Python 3.7+）

```python
@app.route('/')
def index():
    breakpoint()  # 更简洁的断点写法
    return 'Hello'
```

### 方式三：使用 IDE 调试器

在 VS Code 中创建 `.vscode/launch.json`：

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Flask",
            "type": "python",
            "request": "launch",
            "module": "flask",
            "env": {
                "FLASK_APP": "app.py",
                "FLASK_DEBUG": "1"
            },
            "args": [
                "run",
                "--no-debugger",
                "--no-reload"
            ],
            "jinja": true,
            "justMyCode": false
        }
    ]
}
```

## 5. 日志记录

### 基本日志配置

```python
import logging

app.logger.setLevel(logging.INFO)

@app.route('/')
def index():
    app.logger.info('访问了首页')
    app.logger.warning('这是一个警告')
    app.logger.error('这是一个错误')
    return 'Hello'
```

### 日志级别

| 级别 | 数值 | 用途 |
|------|------|------|
| DEBUG | 10 | 详细调试信息 |
| INFO | 20 | 一般信息 |
| WARNING | 30 | 警告信息 |
| ERROR | 40 | 错误信息 |
| CRITICAL | 50 | 严重错误 |

### 自定义日志格式

```python
import logging
from logging.handlers import RotatingFileHandler

# 设置日志格式
formatter = logging.Formatter(
    '%(asctime)s %(levelname)s: %(message)s [in %(pathname)s:%(lineno)d]'
)

# 文件处理器（自动轮转）
file_handler = RotatingFileHandler(
    'logs/app.log', 
    maxBytes=10240000,  # 10MB
    backupCount=10
)
file_handler.setFormatter(formatter)
file_handler.setLevel(logging.INFO)

app.logger.addHandler(file_handler)
```

## 6. 常见开发问题排查

### 问题 1：端口被占用

```bash
# 查看端口占用（Windows）
netstat -ano | findstr :5000

# 查看端口占用（macOS/Linux）
lsof -i :5000

# 解决方案：使用其他端口
flask run --port 5001
```

### 问题 2：修改代码后没有生效

**原因**：调试模式未开启

**解决方案**：
1. 确认 `FLASK_DEBUG=1`
2. 检查 `.env` 文件是否正确
3. 重启服务器

### 问题 3：模板修改后不更新

**解决方案**：

```python
app.config['TEMPLATES_AUTO_RELOAD'] = True
```

## 7. 生产环境注意事项

> ⚠️ **重要警告**：永远不要在生产环境（正式上线时）开启 Debug 模式！

### 为什么？

1. **安全风险**：报错信息会暴露你的代码细节
2. **远程代码执行**：调试器允许在服务器上执行任意代码
3. **性能问题**：调试模式会降低性能

### 生产环境配置

```python
# config.py
class ProductionConfig:
    DEBUG = False
    TESTING = False
    SECRET_KEY = 'your-production-secret-key'
```

## 小结

| 场景 | 推荐做法 |
|------|----------|
| 开发调试 | `flask run --debug` |
| IDE 断点调试 | 配置 launch.json |
| 查看日志 | 使用 app.logger |
| 生产环境 | 关闭 DEBUG，使用 Gunicorn |

> 💡 **提示**：养成使用日志的习惯，它会在生产环境中帮你快速定位问题。
