# 4.1 蓝牙基础概念

ESP32集成了蓝牙功能，支持经典蓝牙和低功耗蓝牙（BLE）。本节将介绍蓝牙的基础概念和ESP32的蓝牙功能。

## 蓝牙概述

### 蓝牙技术分类

| 类型 | 全称 | 特点 |
|------|------|------|
| BR/EDR | Basic Rate/Enhanced Data Rate | 经典蓝牙，适合音频传输 |
| BLE | Bluetooth Low Energy | 低功耗，适合传感器数据 |
| 双模 | Dual Mode | 同时支持经典蓝牙和BLE |

### ESP32蓝牙特性

ESP32支持双模蓝牙：

**经典蓝牙特性：**
- 蓝牙4.2 BR/EDR
- A2DP（高级音频分发）
- SPP（串口配置文件）
- HFP（免提配置文件）

**BLE特性：**
- 蓝牙4.2 BLE
- 支持中心设备和外围设备角色
- 支持多连接
- 支持安全连接

### 蓝牙版本对比

| 版本 | 发布年份 | 主要特性 |
|------|----------|----------|
| 4.0 | 2010 | 引入BLE |
| 4.1 | 2013 | LTE共存、双模改进 |
| 4.2 | 2014 | 数据长度扩展、隐私保护 |
| 5.0 | 2016 | 长距离、高速度、广播扩展 |
| 5.1 | 2019 | 方向定位 |
| 5.2 | 2020 | LE Audio、ISOC |

## BLE基础概念

### BLE架构

```
+-------------------+
|    应用层         |  GATT, GAP
+-------------------+
|    主机层         |  L2CAP, ATT, SMP
+-------------------+
|    控制器层       |  PHY, LL
+-------------------+
```

### GAP（Generic Access Profile）

GAP定义了设备如何发现和连接其他设备。

**设备角色：**
- **外围设备（Peripheral）**：被连接的设备，如传感器
- **中心设备（Central）**：主动连接的设备，如手机

**广播类型：**
- 可连接广播
- 不可连接广播
- 可扫描广播
- 定向广播

### GATT（Generic Attribute Profile）

GATT定义了数据如何组织和传输。

**GATT层级结构：**

```
Profile（配置文件）
  |-- Service（服务）
  |     |-- Characteristic（特征值）
  |     |     |-- Value（值）
  |     |     |-- Descriptor（描述符）
  |     |
  |     |-- Characteristic
  |
  |-- Service
        |-- Characteristic
```

### UUID

UUID用于唯一标识服务和特征值。

**UUID类型：**
- 16位UUID：蓝牙联盟定义的标准UUID
- 128位UUID：自定义UUID

**常用标准UUID：**

| 16位UUID | 服务/特征 |
|----------|-----------|
| 0x1800 | Generic Access |
| 0x1801 | Generic Attribute |
| 0x180A | Device Information |
| 0x180F | Battery Service |
| 0x2A00 | Device Name |
| 0x2A01 | Appearance |
| 0x2A04 | Peripheral Preferred Connection Parameters |
| 0x2A19 | Battery Level |

### 属性权限

| 权限 | 说明 |
|------|------|
| Read | 可读 |
| Write | 可写 |
| Notify | 可通知 |
| Indicate | 可指示（需确认） |

## BLE数据包结构

### 广播包结构

```
广播包格式：

+--------+--------+------------------+
| Length | AD Type| AD Data          |
+--------+--------+------------------+
| 1字节  | 1字节  | (Length-1)字节   |
+--------+--------+------------------+

常用AD Type：
- 0x01: Flags
- 0x02/0x03: Incomplete/Complete List of 16-bit UUIDs
- 0x08/0x09: Shortened/Complete Local Name
- 0x0A: Tx Power Level
- 0xFF: Manufacturer Specific Data
```

### 连接参数

**关键参数：**

| 参数 | 说明 | 范围 |
|------|------|------|
| Connection Interval | 连接间隔 | 7.5ms - 4s |
| Slave Latency | 从设备延迟 | 0 - 499 |
| Supervision Timeout | 超时时间 | 100ms - 32s |

**连接参数优化：**

```cpp
// 高吞吐量配置
connInterval = 7.5ms
slaveLatency = 0
supervisionTimeout = 4000ms

// 低功耗配置
connInterval = 100ms
slaveLatency = 4
supervisionTimeout = 6000ms
```

## ESP32 BLE架构

### 软件架构

```
+-------------------+
|    Application    |
+-------------------+
|    BLE Library    |  Arduino BLE库 / NimBLE
+-------------------+
|    Bluedroid      |  蓝牙协议栈
+-------------------+
|    HCI            |  主机控制器接口
+-------------------+
|    Controller     |  底层控制器
+-------------------+
```

### 内存使用

BLE功能需要较多内存：

| 组件 | 内存占用 |
|------|----------|
| Bluedroid协议栈 | 约50KB |
| BLE库 | 约10KB |
| 应用缓冲 | 约10KB |

### 选择BLE库

**Arduino BLE库：**
- 官方支持
- API简单
- 内存占用较大

**NimBLE库：**
- 内存占用小（约减少50%）
- 性能更好
- API略有不同

## BLE开发流程

### 外围设备开发流程

```
1. 初始化BLE
   |
2. 创建BLE服务器
   |
3. 创建服务和特征值
   |
4. 设置广播数据
   |
5. 开始广播
   |
6. 处理连接和断开事件
   |
7. 处理读写请求
   |
8. 发送通知
```

### 中心设备开发流程

```
1. 初始化BLE
   |
2. 扫描设备
   |
3. 连接目标设备
   |
4. 发现服务
   |
5. 发现特征值
   |
6. 读写特征值
   |
7. 订阅通知
   |
8. 断开连接
```

## 蓝牙安全

### 配对模式

| 模式 | 安全级别 | 说明 |
|------|----------|------|
| Just Works | 低 | 无需用户确认 |
| Passkey | 中 | 输入PIN码 |
| Numeric Comparison | 高 | 确认数字匹配 |
| OOB | 高 | 使用带外通道 |

### 安全等级

| 等级 | 说明 |
|------|------|
| 1 | 无安全 |
| 2 | 未认证加密 |
| 3 | 认证加密 |
| 4 | 认证加密+LESC |
