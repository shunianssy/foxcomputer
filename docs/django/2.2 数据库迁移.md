# 2.2 数据库迁移

Django 的迁移系统是连接模型和数据库的桥梁。通过迁移，你可以将模型变更同步到数据库，无需手动编写 SQL。

## 迁移基础

### 迁移命令

```bash
# 创建迁移文件（检测模型变更）
python manage.py makemigrations

# 指定应用创建迁移
python manage.py makemigrations blog

# 执行迁移（应用到数据库）
python manage.py migrate

# 查看迁移状态
python manage.py showmigrations

# 查看迁移 SQL
python manage.py sqlmigrate blog 0001
```

### 迁移工作流程

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   models.py     │ ──▶ │  makemigrations │ ──▶ │  迁移文件        │
│   定义模型       │     │  检测变更        │     │  0001_initial.py│
└─────────────────┘     └─────────────────┘     └────────┬────────┘
                                                         │
                                                         ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│    数据库        │ ◀── │    migrate      │ ◀── │  执行迁移        │
│   表结构更新     │     │  应用迁移        │     │  创建/修改表     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

## 迁移文件结构

### 初始迁移

```python
# blog/migrations/0001_initial.py
from django.db import migrations, models

class Migration(migrations.Migration):

    initial = True

    dependencies = [
        # 依赖其他应用的迁移
        ('auth', '0012_alter_user_first_name_max_length'),
    ]

    operations = [
        migrations.CreateModel(
            name='Article',
            fields=[
                ('id', models.BigAutoField(
                    auto_created=True,
                    primary_key=True,
                    serialize=False,
                    verbose_name='ID'
                )),
                ('title', models.CharField(max_length=100)),
                ('content', models.TextField()),
                ('created_at', models.DateTimeField(auto_now_add=True)),
            ],
        ),
    ]
```

### 后续迁移

```python
# blog/migrations/0002_article_status.py
from django.db import migrations, models

class Migration(migrations.Migration):

    dependencies = [
        ('blog', '0001_initial'),
    ]

    operations = [
        migrations.AddField(
            model_name='article',
            name='status',
            field=models.CharField(
                choices=[('draft', '草稿'), ('published', '已发布')],
                default='draft',
                max_length=20
            ),
        ),
    ]
```

## 常用迁移操作

### 添加字段

```python
# 模型中添加字段后
class Article(models.Model):
    title = models.CharField(max_length=100)
    content = models.TextField()
    # 新增字段
    author = models.ForeignKey('auth.User', on_delete=models.CASCADE)
```

```bash
# 创建迁移
python manage.py makemigrations
# You are trying to add a non-nullable field 'author' to article without a default;
# we can't do that (the database needs something to populate existing rows).
# Please select a fix:
# 1) Provide a one-off default now (will be set on all existing rows)
# 2) Quit, and let me add a default in models.py
```

### 处理非空字段

```python
# 方式1：设置默认值
author = models.ForeignKey(
    'auth.User',
    on_delete=models.CASCADE,
    default=1  # 设置默认用户ID
)

# 方式2：允许为空
author = models.ForeignKey(
    'auth.User',
    on_delete=models.CASCADE,
    null=True
)

# 方式3：在迁移时提供默认值
# 选择选项1，输入默认值
```

### 删除字段

```python
# 在迁移文件中
operations = [
    migrations.RemoveField(
        model_name='article',
        name='old_field',
    ),
]
```

### 重命名字段

```python
operations = [
    migrations.RenameField(
        model_name='article',
        old_name='body',
        new_name='content',
    ),
]
```

### 重命名模型

```python
operations = [
    migrations.RenameModel(
        old_name='Post',
        new_name='Article',
    ),
]
```

## 数据迁移

除了结构变更，还可以迁移数据：

### 创建空迁移

```bash
python manage.py makemigrations --empty blog
```

### 编写数据迁移

```python
# blog/migrations/0003_populate_categories.py
from django.db import migrations

def create_default_categories(apps, schema_editor):
    """创建默认分类"""
    # 使用 apps.get_model 获取模型的历史版本
    Category = apps.get_model('blog', 'Category')
    
    categories = [
        {'name': '技术', 'slug': 'tech'},
        {'name': '生活', 'slug': 'life'},
        {'name': '随笔', 'slug': 'essay'},
    ]
    
    for cat in categories:
        Category.objects.create(**cat)

class Migration(migrations.Migration):

    dependencies = [
        ('blog', '0002_article_status'),
    ]

    operations = [
        migrations.RunPython(create_default_categories),
    ]
```

### 数据迁移示例：合并字段

```python
def merge_names(apps, schema_editor):
    """将 first_name 和 last_name 合并为 full_name"""
    Person = apps.get_model('blog', 'Person')
    
    for person in Person.objects.all():
        person.full_name = f"{person.first_name} {person.last_name}"
        person.save(update_fields=['full_name'])

class Migration(migrations.Migration):
    dependencies = [
        ('blog', '0003_add_full_name'),
    ]

    operations = [
        migrations.RunPython(merge_names),
    ]
```

## 回滚迁移

### 查看迁移历史

```bash
python manage.py showmigrations blog

# 输出：
# blog
#  [X] 0001_initial
#  [X] 0002_article_status
#  [X] 0003_populate_categories
```

### 回滚到指定版本

```bash
# 回滚到指定迁移
python manage.py migrate blog 0002

# 回滚所有迁移
python manage.py migrate blog zero
```

### 伪造迁移

当数据库已经存在表结构时：

```bash
# 标记迁移已执行，但不实际执行
python manage.py migrate --fake blog 0001
```

## 迁移最佳实践

### 1. 小步迁移

```python
# 不要一次性做太多变更
# 推荐：每次只做一种变更

# 好的做法
# 迁移1：添加字段
# 迁移2：创建索引
# 迁移3：数据迁移

# 不推荐
# 一个迁移包含多种变更
```

### 2. 可逆迁移

```python
def create_categories(apps, schema_editor):
    Category = apps.get_model('blog', 'Category')
    Category.objects.create(name='技术')

def delete_categories(apps, schema_editor):
    Category = apps.get_model('blog', 'Category')
    Category.objects.filter(name='技术').delete()

class Migration(migrations.Migration):
    operations = [
        migrations.RunPython(
            create_categories,
            reverse_code=delete_categories  # 提供回滚函数
        ),
    ]
```

### 3. 使用模型版本

```python
def migrate_data(apps, schema_editor):
    # 使用 apps.get_model 而不是直接导入模型
    # 这样可以获取迁移时的模型版本
    Article = apps.get_model('blog', 'Article')
    
    for article in Article.objects.all():
        # 处理数据
        pass
```

### 4. 团队协作

```bash
# 在合并代码前，确保迁移没有冲突
python manage.py makemigrations --check
```

## 常见问题

### 问题1：迁移冲突

```bash
# 解决方案：合并迁移
python manage.py makemigrations --merge
```

### 问题2：数据库已存在

```bash
# 方案1：伪造初始迁移
python manage.py migrate --fake

# 方案2：重置迁移
# 删除所有迁移文件和数据库
# 重新创建迁移
python manage.py makemigrations
python manage.py migrate
```

### 问题3：迁移卡住

```bash
# 查看当前迁移状态
python manage.py showmigrations

# 强制标记迁移状态
python manage.py migrate --fake blog 0002
```

## 多数据库迁移

```python
# settings.py
DATABASES = {
    'default': {...},
    'replica': {...},
}

DATABASE_ROUTERS = ['myapp.routers.PrimaryReplicaRouter']
```

```bash
# 指定数据库迁移
python manage.py migrate --database=default
python manage.py migrate --database=replica
```

## 小结

数据库迁移的关键点：

1. **创建迁移**：`makemigrations` 检测模型变更
2. **执行迁移**：`migrate` 应用到数据库
3. **数据迁移**：使用 `RunPython` 迁移数据
4. **回滚迁移**：可以撤销已执行的迁移
5. **最佳实践**：小步迁移、可逆迁移、团队协作

> 💡 **提示**：迁移是 Django 的强大功能，但也需要谨慎使用。在生产环境执行迁移前，务必备份数据库！
